## 为什么还要学这一课？

你第 3 课发现：**登录很慢，商品列表很快。**

现在脚本是这样跑的：

```text
每个虚拟用户：登录 → 查商品 →（循环再登录 → 再查商品）
```

问题：聚合报告里「商品列表」的压力，混着大量登录时间，**测不准读接口本身**。

更标准的写法：

```text
setUp 线程组：登录 1 次，提出 token（只做准备）
        ↓
正式线程组：很多人只查商品列表（真正压测）
```

像考试前先发准考证（登录），考试时大家一起答题（压读接口）。

## 步骤 2：添加「setUp线程组」

1. 右键 **测试计划**
2. **添加 → 线程（用户）→ setUp线程组**

setUp 线程组特点：**整个测试开始时先跑完它**，再跑普通线程组。

### setUp线程组参数

| 项 | 填什么 |
|----|--------|
| 名称 | `准备-登录` |
| 线程数 | `1` |
| Ramp-Up | `1` |
| 循环次数 | `1` |

只要登录一次。

## 步骤 3：把「登录」挪到 setUp 里

两种做法任选：

**做法 A（推荐）**  
- 在 setUp 下重新加一个「登录」HTTP请求（和以前一样：POST、Body、Content-Type）  
- 再挂 **JSON提取器**：变量 `token`，表达式 `$.data.token`

**做法 B**  
- 把原来的「登录」节点拖到 setUp线程组下面（注意信息头、提取器一起带走）

### 关键：让 token 给后面线程组用

JSON提取器默认变量只在当前线程里。跨线程组要用「属性」。

在 **提取token（JSON提取器）** 下面，再加一个：

右键 **登录** → **添加 → 后置处理器 → BeanShell后置处理程序**  
（有的版本叫 **JSR223后置处理程序**，语言选 groovy 也可以）

#### 若用 BeanShell后置处理程序

脚本框填一行：

```java
props.put("token", vars.get("token"));
```

意思：把变量 `token` 存成**全局属性**，别的线程组也能读。

#### 若用 JSR223后置处理程序（推荐，更稳）

- 语言选：`groovy`
- 脚本：

```groovy
props.put("token", vars.get("token"))
```

## 步骤 4：改正式线程组（只压商品列表）

1. 原来的「登录压测」改名为：`商品压测`
2. **删掉或禁用** 里面的「登录」（不要再每个用户都登录）
3. 只保留 **商品列表** + 它的信息头

### 商品列表的 Authorization 改成读属性

信息头里原来可能是：

```text
Bearer ${token}
```

改成：

```text
Bearer ${__P(token)}
```

说明：

- `${token}` = 当前线程变量（setUp 里的别的线程拿不到）
- `${__P(token)}` = 读全局属性（setUp 存进去的）

### 商品压测线程组参数（本课）

| 项 | 填什么 |
|----|--------|
| 线程数 | `10` |
| Ramp-Up时间（秒） | `5` |
| 循环次数 | `5` |

这样主要压力打在商品列表上。

## 排错：商品列表 10004 / 异常% 很高

### 现象 A：登录绿，商品列表红（Token 无效）

**最常见原因**：请求头还在用 `${token}`。

改成：

```text
Authorization = Bearer ${__P(token)}
```

`${token}` 只在当前线程组有效；跨组必须用 `${__P(token)}`。

### 现象 B：聚合报告里「登录」样本有几十上百（不是 1）

说明「准备-登录」还是**普通线程组**，或线程数/循环 > 1。

请确认：

1. 节点类型是 **setUp线程组**（不是「线程组」）
2. setUp 里：线程数=`1`，循环=`1`
3. 「商品测试」里**没有**登录请求

### 现象 C：商品列表大约一半失败

常见于两个**普通线程组同时跑**：商品组启动时登录还没写完 `props`。

处理：准备-登录必须用 setUp；改完后先 **清除所有** 再跑。

### 快速自检

1. 清除所有 → 启动  
2. 结果树点一条绿的「商品列表」→ 看「请求」里 Header  
3. 应出现 `Authorization: Bearer eyJ...`（很长一串）  
4. 若仍是 `Bearer ${token}` 或 `Bearer ` 后面为空 → 头没改对 / 属性没存上
