# 测试场景清单（第三阶段重点）

用于 Postman / Pytest 设计用例。断言时同时检查 HTTP Status 与 `code`。

## 购物车

| 场景 | 预期 HTTP | 预期 code |
|------|-----------|-----------|
| 正常加入商品 | 200 | 200 |
| 重复加入同商品（合并数量） | 200 | 200 |
| 加入不存在商品 | 404 | 20001 |
| 加入 OFF_SALE 商品 | 409 | 20002 |
| quantity=0 / -1 | 400 | 90001 或 30002 |
| quantity > stock | 409 | 20003 |
| 修改购物车数量 | 200 | 200 |
| 修改为 0 | 400 | 90001 |
| 删除自己的购物车项 | 200 | 200 |
| 删除不存在项 | 404 | 30001 |
| user02 删除/修改 user01 的购物车项 | 403 | 30004 |
| 查看自己的购物车 | 200 | 200 |
| 清空购物车（只清自己） | 200 | 200 |

## 订单创建

| 场景 | 预期 HTTP | 预期 code |
|------|-----------|-----------|
| 直接 items 下单成功 | 200 | 200 |
| 购物车结算成功 | 200 | 200 |
| checkoutAll 结算全部 | 200 | 200 |
| 空参数（无 cart/items） | 400 | 40010 |
| 商品不存在 | 404 | 20001 |
| 商品下架 | 409 | 20002 |
| 库存不足 | 409 | 20003 |
| 多商品部分库存不足整单回滚 | 409 | 20003（库存/订单均无脏数据） |
| 客户端乱传 totalAmount 被忽略 | 200 | 金额=服务端计算 |

## 订单取消 / 幂等

| 场景 | 预期 |
|------|------|
| PENDING 取消成功 | 200；库存恢复；流水 ORDER_CANCEL_RESTORE |
| 重复取消 | 409 / 40005；库存不再增加 |
| PAID 订单取消 | 409 / 40005 |

## 订单状态机

| 操作 | 合法 | 非法示例 |
|------|------|----------|
| pay | PENDING→PAID | PAID→PAID、SHIPPED→PAID → 409/40006 |
| ship | PAID→SHIPPED | PENDING→SHIPPED → 409/40007 |
| complete | SHIPPED→COMPLETED | PAID→COMPLETED → 409/40008 |

## 权限隔离

| 场景 | 预期 |
|------|------|
| user02 查看 user01 订单 | 403 / 40009 |
| user02 取消 user01 订单 | 403 / 40009 |
| USER 调用 pay/ship/complete | 403 / 10008 |
| ADMIN 可查看全部订单 | 200 |

## 价格快照

1. 创建订单记下 order_items.product_price  
2. 管理员修改商品价格  
3. 再查历史订单，快照价格不变
